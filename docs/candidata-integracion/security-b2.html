Compilation and assembly run locally in the browser through WebAssembly. Before instantiating the module, the interface computes its SHA-256 and also checks the declared byte size; a mismatch prevents initialization.

2. Source profile and language separation

  • Source-profile selection is explicit: es or en.
  • There is no language autodetection.
  • Changing the interface language cannot modify source bytes or active source profiles.
  • Changing a source profile never translates or rewrites the program.
  • SVP-ES and SVP-EN are interpreted before the shared parser and use the same internal identities.

3. Interface controls

  • The content security policy restricts scripts, styles, connections, images and fonts to the same origin, except for the explicit capabilities required for WebAssembly and embedded data.
  • The interface limits each source unit to 1 MiB.
  • UTF-8 result decoding is fatal: invalid byte sequences are not silently replaced.
  • The interface computes the SHA-256 of the current source and, when present, compares it with the source_sha256 returned by compilation.
  • Downloading source preserves its text; no automatic translation or transformation is applied.

4. File assembly

B2 keeps two source units with independent profiles. It does not concatenate text or lexical sequences across files. Each unit is analyzed under its own profile and joint validation takes place after both representations have been integrated into one IR.

5. Known limits

  • B2 remains a public experimental version and is not a stable release.
  • Browser, static-hosting and external delivery-chain security lie outside compiler semantics.
  • Visual Unicode security in strings, comments and other presentation forms is not declared resolved.
  • The existence of two units in B2 does not yet establish a general project infrastructure or an arbitrary module count.
  • These controls do not replace a security review before any inclusion in the stable release.
