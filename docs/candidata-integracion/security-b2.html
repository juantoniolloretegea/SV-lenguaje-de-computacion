Security

Observable security controls and limits of the published implementation.

Back to the SV workspaceVersion history
Scope. Verifiable controls of the published implementation; this is neither a general security certification nor, by itself, a statement of grammatical conformity.

1. Identity and execution

Compilation and assembly run locally in WebAssembly. The module's exact identity is declared in build-info.json. Before instantiation, the interface checks SHA-256, byte length and the presence of required exports. These checks establish material identity and loadability of the artifact; Language conformity is tested separately by the regression suites.

2. Source profile and isolation

  • Explicit es/en selection; no autodetection.
  • Interface language does not modify source or source profiles.
  • Changing the source profile does not translate or alter program bytes.
  • Assembly never concatenates text or token streams across files.
  • Closed grammatical domains are checked after common canonicalization, so there are no language-specific duplicate validators.

3. Interface controls

  • Restrictive Content Security Policy.
  • 1 MiB source-unit limit in the interface.
  • Strict UTF-8 result decoding.
  • Source SHA-256 is checked when compilation returns a digest.

4. Limits

  • Browser, hosting and external delivery-chain security are outside compiler semantics.
  • Visual Unicode security is not declared solved.
  • Two units do not establish a general project or arbitrary-module infrastructure.
  • General regime and the known ConflictOperator/J2.3 debt remain outside this correction's scope.
  • Technical correction of a debt does not by itself enable a later phase; continuity is governed separately by Quality.
