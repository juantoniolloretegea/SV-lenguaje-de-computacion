Features

Verified properties of the published bilingual implementation and its multi-source assembly.

Scope. This page describes verified properties of the published bilingual implementation; it does not extend guarantees beyond the stated evidence.

1. Computational identity

SVP-ES and SVP-EN are two explicit language profiles of one implementation. Surface spellings are resolved before parsing and converge on the same internal identities, parser, IR and semantics.

  • Accepted profiles: es and en.
  • There is no language autodetection.
  • Changing interface language does not change the source profile.
  • User identifiers, strings, comments and data are not translated.

3. Multi-source assembly

The published implementation accepts two .svp units with independent profiles. Each unit is parsed under its own profile; text and token streams are never concatenated. Canonical representations are merged and global well-formedness is checked after the merge.

EN+EN, EN+ES, ES+EN and ES+ES were accepted by the positive suite; wrong profile, duplicate global identifier and syntax split across files were rejected.

4. Implementation regression

The current corpus contains 79 cases: 12 valid and 67 invalid. B2 regression preserved R0 differential equivalence over all 79 cases, native/WASI/browser parity, and the ten R1 criteria within their closed scope.

The browser WebAssembly for this implementation is 377812 bytes, SHA-256 03a958e5c24a23aebfab6d68aaa24e40d83085127b7a2bc7d23fd27a27ac6e03.

5. Limits

  • Two-unit assembly is not yet a general project or arbitrary-module infrastructure.
  • Exact diagnostic-text parity across implementations has not been established.
  • Visual Unicode security is not declared solved.
  • Inherited core debts remain separately governed by Quality and are not closed by this interface.
