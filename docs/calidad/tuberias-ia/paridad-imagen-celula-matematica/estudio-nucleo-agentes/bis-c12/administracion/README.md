# Operaciones y código conservado · C12

Preparación y registro efectivos mediante JavaScript en functions.exec; lectura y escritura mediante el conector GitHub. Se conservan preparar.js, registrar.js, verificar.js y publicar.js. Dependen de load/store y tools del entorno; no se presentan como ejecutables autónomos ni como implementación de SV. Las entradas de continuidad deben recuperarse exactamente de los cortes de FUENTES.json.

El servidor de ejecución se desconectó tras las lecturas locales. La creación de un preparador Python no obtuvo confirmación y éste no se ejecutó. No se invocó cargo ni rustc para C12. La reconstrucción y sincronización local quedan pendientes. No hay simulación de esos resultados.

La publicación crea blobs, árbol basado en el corte, commit y avance sin fuerza, primero laboratorio y después público. Se comprueba que los blobs anteriores ajenos a la entrega permanezcan iguales, que los nuevos coincidan con los creados y que las cabeceras remotas correspondan al commit publicado. Los SHA de los commits finales se comunican después; no se predicen aquí.

El código de preparación genera entradas y contrato; registrar.js actualiza sólo S22, conserva S24 y añade historial/RETP. verificar.js coteja documentos y mutantes, no compila SVP. Las identidades de los archivos son las de sus blobs Git en el commit. Las entradas textuales no equivalen a ensayo ejecutado.
